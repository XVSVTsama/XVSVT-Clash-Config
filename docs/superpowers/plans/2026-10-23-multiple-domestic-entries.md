# 国内入口多节点实现计划

**目标：** 每个运营商可维护多个国内入口节点，由单一入口解析开关注入；强制按运营商命名编号，且不进入其他代理组。

**架构：** 维护区使用 telecom/unicom/mobile 数组，按数组顺序生成电信入口解析-01、联通入口解析-01、移动入口解析-01 等名称。入口仅在 DNS 合并完成后注入专用组，其他组保留原动态加载与筛选，并追加排除规则。

**技术栈：** 原生 JavaScript、Node.js node:test、Mihomo。

## 约束与审查重点

- 入口解析默认关闭；保持现有节点参数和 DNS 后缀逻辑。
- 自定义 name 必须被覆盖，每个运营商独立从 01 开始编号，超过 99 不截断。
- 动态 include-all / include-all-proxies、显式 proxies、default-selected 都不得引入入口节点；既有 exclude-filter 必须保留。
- 全部数组为空时不生成空组、不改 DNS；支持部分运营商为空。
- 输入节点列表和维护区不得因注入而累积修改；同名订阅节点不得覆盖维护区定义。
